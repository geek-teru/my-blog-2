スタイルガイド

Teru's Home の見た目の決まりごと。値そのものより、なぜその値なのかを残すことを目的にしています。 実装は src/styles/global.css と各コンポーネントにあります。

設計の前提

個別の値を決める前に置いた、共通の判断軸。

和文を主役にする

出発点は Astro の blog テンプレート（Bear Blog ベース）でしたが、数値はすべて欧文向けでした。 日本語の記事を載せる以上、そのままでは成立しません。文字サイズ・行間・字送り・見出しスケールは すべて和文基準で引き直しています。

なぜ: 和文は欧文より字面が詰まり、漢字の密度が高い。欧文向けの line-height: 1.7 や本文の 3 倍を超える見出しは、日本語だと圧迫感と情報量の低下を招く。

囲みより罫線

影・グラデーション・塗りつぶしを減らし、1px の罫線で領域を分けています。 装飾を足すのは、意味の区別が必要な場所（カード、目次の現在地）に限ります。

読み物の幅を守る

記事本文の列幅は 44rem から広げません。一覧ページだけ 64rem に広げ、カードを3列並べます。

文字

本文 17px / 行間 1.9 / 字送り 0.02em を基準にしています。

フォントスタック

FONT-FAMILY
var(--font-atkinson), 'Hiragino Sans', 'Hiragino Kaku Gothic ProN', 'Yu Gothic Medium', 'Yu Gothic', Meiryo, 'Noto Sans JP', sans-serif
なぜ Web フォントを使わないのか: 欧文は雛形付属の Atkinson、和文は OS 同梱のゴシックへ落とす。 Atkinson は日本語グリフを持たないため、フォールバックが無いと豆腐（□）になる。 和文 Web フォントを配信する案もあるが、CJK はサブセットが桁違いに大きく、 subsets に japanese を明示しないとかえって表示できない。 読みやすさの改善に見合わないため採用していない。

レイアウト

列幅は --measure ひとつで制御しています。

MEASURE
--measure: 44rem（記事本文・固定ページ）
html.wide → 64rem（トップ・記事一覧）
なぜ変数ひとつで切り替えるのか: ヘッダー・パンくず・フッターも同じ --measure を見ている。 html に .wide を付けるだけで全部が同時に追従するので、 ページごとに幅がずれることがない。
トークン 値 用途
--measure 44rem 読み物の幅。記事・Profile・Career・404
html.wide 64rem カードを3列並べる一覧ページ
--radius 8px カード・画像・コードブロック・囲み
--header-h 実測値 sticky ヘッダーの高さ。目次の追従位置とアンカーの逃がし量が依存する

記事ページの2カラム

見出しが2つ以上ある記事だけ、240px / 1fr の2カラムにして左に目次を置きます。 960px 未満では目次が本文の上に戻ります。

なぜ条件付きなのか: Profile / Career のように見出しを持たないページで空のサイドバーが開くのを避けるため。 判定は BlogPost.astro の hasToc と TableOfContents.astro のフィルタで二重に持っているので、 条件を変えるときは両方直すこと。

ヘッダーの高さは実測する

--header-h に CSS の初期値を置きつつ、Header.astro が 自分の offsetHeight を測って上書きします。ResizeObserver で 幅の変化にも追従します。

なぜ実測なのか: 目次の top、見出しの scroll-margin-top、現在地判定の オフセットの3つが、すべてヘッダーの高さに依存している。数値で書いておくと、 段数やパディングを変えた瞬間に3箇所が同時にずれる。 実際、ヘッダーを2段にしたときにこれが起きた。高さの出どころをヘッダー自身ひとつに絞り、 依存する側は変数を見るだけにしている。

1段目にサイト名と検索窓、2段目にメニュー。現在地は太字と不透明度だけで示します。 下線は本文のリンクと紛らわしいため使いません。

2段の区切りについて: 2段目は白 12% の細い罫線で分けるだけにしている。別の色を敷くと、 ひとつのヘッダーではなく帯が二つ並んでいるように見える。

決めごとが4つ:
① 列数は固定せず auto-fill + minmax(17rem, 1fr) に任せる。 固定すると記事が1〜2本の時期に空の枠ができる。

作成中の箱

WIP NOTICE

作成中です。

中身を書いたら WipNotice ごと消します。ページ自体は先に用意しておきます。 メニューのリンクが 404 になるのを避けるためです。

動き

トップページのアイキャッチと、読書中の補助だけ。装飾のための動きは置きません。

共通の決まり

  • prefers-reduced-motion: reduce の人には完成した状態を出す。 アニメーションを止めるだけだと初期値（scaleY(0) / opacity: 0）で固まり、線も丸も消える
  • 外部のアニメーションライブラリは足さない
  • 動いている間にレイアウトがずれない。高さは先に確保する
  • 本文は最初から HTML に入れる。JS で組み立てると、動かない環境で中身が消える

ターミナル（トップの導入）

$ cat README.md が打ち込まれ、ひと呼吸おいて中身が出ます。 打鍵の間隔は 45〜100ms でばらつかせています。等間隔だと機械的に見えるためです。

コマンドを cat README.md にした理由: 出力が「H1 + 説明文」という形になり、<h1> をそのまま出力行として 使える。whoami だとサイト名が出るのが不自然になる。

打ち始める前に高さを固定している: 打つにつれて背が伸びると、下のコミットグラフが押し下げられて画面が揺れる。 代償として打っている 1.5 秒ほどは枠内に空白ができるが、揺れないほうを選んだ。 隠すのに display: none ではなく visibility: hidden を 使うのも、高さを失わないため。

コミットグラフ（トップの記事一覧）

記事をコミットに見立てて縦のブランチ線に並べます。線が 0.9 秒かけて上から伸び、 それを追いかけて丸が 0.16 秒ずつずれて灯ります。

作り話の情報は足さない: コミットハッシュ風の文字列を並べればそれらしくなるが、 実在しない値を本物に見える形で出すことになる。 線・丸・ブランチ名（実際に main で運用している）だけで見立てを作る。

丸はグリッドの1列目に置く: 絶対配置にすると基準の箱が行ごとに変わり、線と丸の中心が噛み合わない。 同じ列に入れておけばずれようがない。実装中に2回ずらしてから、この形に落ち着いた。

トップの構成について

トップは「ターミナル（入口の挨拶）」→「コミットグラフ（積み上がってきたもの）」の順。 記事一覧ページ（/blog）はカードのままで、 トップと一覧で見せ方が違います。意図的な非対称です。 トップは眺めるところ、一覧は探すところ、と役割が違うため。

運用の決まり

次に手を入れる人（＝将来の自分）向け。

守ること

  • 色は必ずトークン経由で使う。コンポーネントに直値を書かない
  • 用途が違う色はトークンを分ける。リンクの青と「いまここ」の水色を共用しない
  • 記事本文の列幅 44rem は広げない
  • 負のマージンで余白を打ち消さない。横スクロールの原因になる
  • 横に溢れうるもの（表・コードブロック）は、ページではなく自分の中でスクロールさせる
  • 枠線を持つ丸や箱には box-sizing: border-box を明示する。 このプロジェクトにグローバルな border-box 指定は無く、 既定の content-box のままだと中心の計算に枠線ぶんが乗らない
  • JS が innerHTML で作った要素に、Astro のスコープ付き CSS は当たらない。 スコープ用の属性が付かないため。:global() で抜ける

二重に持っている値

片方だけ直すとずれるので、対で直します。

値 場所
目次を出す条件（h2/h3 が2つ以上） TableOfContents.astro と BlogPost.astro の hasToc
sticky ヘッダーの高さを見込んだ余白 解消済み。3箇所に散っていたが、Header.astro が 実測して --header-h に流す形にした。依存する側は変数を見るだけ
トップの説明文 consts.ts の SITE_DESCRIPTION（メタタグ用）と TerminalIntro.astro の本文。似た文面を別々に持っている
このガイドの色と文字の値 このファイルと src/styles/global.css

まだ決めていないこと

  • ダークモード。トークンで組んであるので追加はしやすい
  • タグ別の一覧ページ。いまタグは表示だけでリンクではない
  • OGP 画像。既定値が Astro のプレースホルダ画像のまま
  • ファビコンが Astro の既定のまま。タブに出るのは Astro のロゴ
  • トップにターミナルとコミットグラフの両方を置いている。情報量が増え、 静かなデザインからは一歩離れた。片方に絞る余地はある
  • グローバルな box-sizing: border-box。入れるべきだが、 既に組んだカード・検索窓・目次の寸法が一斉に変わるので、 各所を再確認する前提の別作業にする
このガイドは手で書き写したもので、CSS とは自動同期しません。トークンを変えたら src/styles/global.css とこのファイルの両方を直してください。
